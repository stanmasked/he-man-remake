# Stage 094 — source RGB / optical verifier parity

Purpose: test the **actual C99 640×360 image bytes** emitted by the
authored three-room renderer against the **unchanged Python pixel-decoding
routines** that will eventually inspect native NeXium guest PNGs.

The full source-native Right/A/B schedule runs for 1190 game frames and
renders 18 source frames. The C99 test writes only independent raw
`source-frame-NNNN.rgb` files: never PNG, fake guest screenshots, emulator
logs, guest controller receipts or claims about original iOS content.
All RGB data is generated by the existing C renderer at run time; both
GCC and Clang are exercised.

The source-to-Python bridge imports the *exact production optical reader
functions* `describe`, `_digit`, `_overlay`, and `_world_y`. It verifies
full three-stage 3×5 glyphs, native CLEAR, FINISH and B replay, fixed world
markers, hazard/respawn and final 2-frame RGB stability. The workflow
deliberately corrupts the FINISH glyph in one raw C99 frame after the
positive check and **requires rejection**.

This is only a **host C99 → Python parser interoperability** check. It
does not create any evidence about guest AArch64 execution or NeXium,
which must still deliver real guest `frame_rx` PNGs and HID transcript
under [Issue #97](https://github.com/stanmasked/he-man-remake/issues/97).
A green result must never be described as emulator verification.

No changes to physics, collision maps, player or enemy mechanics, NRO
source, commercial game data, or original private IPA are introduced.
